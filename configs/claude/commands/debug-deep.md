## Debugging Methodology

### 1. Problem Definition
- Clearly define the issue and symptoms
- Identify when the problem started
- Determine reproducibility and frequency
- Gather environmental context

### 2. Hypothesis Formation
- List potential root causes
- Prioritize hypotheses by likelihood
- Consider both obvious and subtle causes
- Factor in recent changes or deployments

### 3. Evidence Collection
- Examine logs and error messages
- Check system metrics and performance
- Analyze code paths and data flow
- Review recent changes and deployments

### 4. Systematic Investigation
- Test each hypothesis methodically
- Use debugging tools and techniques
- Isolate components and variables
- Trace execution flow

### 5. Root Cause Analysis
- Identify the fundamental cause
- Distinguish between symptoms and causes
- Consider contributing factors
- Document the failure chain

### 6. Solution Development
- Develop immediate fixes
- Plan long-term solutions
- Consider prevention strategies
- Test solutions thoroughly

## Investigation Process

### 🔍 **Initial Assessment**
- **Symptoms**: What is observed to be wrong?
- **Impact**: How severe is the issue?
- **Scope**: What systems/users are affected?
- **Timeline**: When did it start? Any patterns?

### 🧪 **Hypothesis Testing**
For each potential cause:
1. **Hypothesis**: What might be causing this?
2. **Test**: How can we verify this hypothesis?
3. **Evidence**: What would confirm or refute it?
4. **Result**: What did we find?

### 📊 **Data Analysis**
- **Logs**: Error messages, stack traces, patterns
- **Metrics**: Performance indicators, resource usage
- **Code**: Recent changes, potential bugs
- **Environment**: Configuration, dependencies, infrastructure

### 🔧 **Debugging Tools**
Recommend and use appropriate tools:
- **Profilers**: Memory, CPU, network analysis
- **Debuggers**: Step-through debugging
- **Monitoring**: Real-time system observation
- **Tracing**: Distributed system analysis

### 🎯 **Root Cause**
- **Primary Cause**: The fundamental issue
- **Contributing Factors**: What made it worse?
- **Failure Chain**: How did it propagate?
- **Prevention**: How to avoid in the future?

### 💡 **Solutions**

#### Immediate Fix
- **Quick Solution**: Stop the bleeding
- **Workaround**: Temporary mitigation
- **Rollback**: If applicable
- **Monitoring**: Verify fix effectiveness

#### Long-term Solution
- **Permanent Fix**: Address root cause
- **Code Changes**: Required modifications
- **Testing**: Validation strategy
- **Deployment**: Rollout plan

#### Prevention
- **Monitoring**: Early detection
- **Testing**: Prevent regressions
- **Documentation**: Knowledge sharing
- **Process**: Workflow improvements

### 🚨 **Risk Assessment**
- **Severity**: How critical is this issue?
- **Probability**: Likelihood of recurrence
- **Impact**: Potential damage if it happens again
- **Mitigation**: Risk reduction strategies

### 📈 **Success Metrics**
- **Resolution Time**: How quickly was it fixed?
- **Recurrence**: Has it happened again?
- **User Impact**: Measured improvement
- **Team Learning**: Knowledge gained

Use systematic debugging practices to identify and resolve complex technical issues efficiently.
